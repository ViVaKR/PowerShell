# Module

## 동사 클래스


```csharp
[Cmdlet(VerbsCommon.New, "ModuleForge")]
public class NewModuleForgeCommand : PSCmdlet
{
    protected override void ProcessRecord() => WriteObject("만들었습니다");
}
```

문자열로 직접 써도 동작합니다. 다만 **승인된 동사** 목록과 철자가 틀려도 컴파일러가 못 잡으니, 상수를 쓰는 편이 안전합니다.

```csharp
[Cmdlet("New", "ModuleForge")]   // 동작은 하지만 오타를 못 잡음
```

## 동사 클래스 지도

| 클래스 | 성격 | 대표 동사 |
|---|---|---|
| `VerbsCommon` | 일반 작업 | Get, Set, **New**, Remove, Add, Clear, Copy, Move, Find, Select, Show, Open, Close, Rename, Reset |
| `VerbsData` | 데이터 가공 | Convert, ConvertTo, ConvertFrom, Export, Import, Update, Save, Merge, Compare, Edit, Out, Publish, Restore, Sync |
| `VerbsLifecycle` | 수명주기 | Start, Stop, Install, Uninstall, Enable, Disable, Invoke, Register, Unregister, Wait, Restart |
| `VerbsDiagnostic` | 진단 | Test, Resolve, Measure, Debug, Trace, Ping, Repair |
| `VerbsCommunications` | 통신 | Connect, Disconnect, Send, Receive, Read, Write |
| `VerbsSecurity` | 보안 | Grant, Revoke, Block, Unblock, Protect, Unprotect |
| `VerbsOther` | 기타 | Use |

정확한 목록은 pwsh에서 바로 볼 수 있습니다.

```powershell
Get-Verb | Sort-Object Group, Verb          # 승인된 동사 전체와 그룹
Get-Verb New                                 # New의 그룹 확인
Get-Verb -Group Common
```

`Get-Verb` 결과의 `Group` 열이 곧 C#의 `Verbs<Group>` 클래스 이름과 대응합니다. 예를 들어 Group이 `Lifecycle`이면 `VerbsLifecycle`입니다. 목록은 pwsh 버전에 따라 조금 늘 수 있으니 `Get-Verb`이 가장 정확합니다.

## 승인되지 않은 동사를 쓰면?

빌드는 되고 모듈 로드도 되지만, `Import-Module` 때 **경고**가 나옵니다. 그리고 Gallery에 올린 모듈의 품질 평가에서도 감점 요인이 될 수 있습니다. 가능하면 승인된 동사 중에서 고르세요.

## New를 만들 때 알아둘 점

`New-` 계열은 무언가를 **생성**하므로 `-WhatIf`/`-Confirm`을 지원하는 것이 관례입니다.

```csharp
[Cmdlet(VerbsCommon.New, "ModuleForge", SupportsShouldProcess = true)]
public class NewModuleForgeCommand : PSCmdlet
{
    [Parameter(Position = 0, Mandatory = true)]
    public string Name { get; set; } = "";

    protected override void ProcessRecord()
    {
        if (ShouldProcess(Name, "모듈 생성"))
        {
            // 실제 생성 로직
            WriteObject($"{Name} 생성 완료");
        }
    }
}
```

## 스캐폴더에 반영하려면

지금 스크립트는 샘플 cmdlet 동사를 `Test`로 고정해서 만듭니다. 이 부분을 파라미터로 받으면 편해집니다.

```powershell
[ValidateSet('New','Get','Test','Resolve','Invoke')]
[string]$Verb = 'Test'
```

그리고 C# 템플릿에서는 동사가 속한 클래스 이름이 다르므로, `Test`/`Resolve`는 `VerbsDiagnostic`, `New`/`Get`은 `VerbsCommon`처럼 매핑하는 작은 표가 필요합니다. 가장 간단한 방법은 템플릿에서 `[Cmdlet("$Verb", "$Noun")]`처럼 **문자열 리터럴**로 쓰는 것입니다. 이러면 매핑표가 필요 없고, 승인 동사 검증은 스크립트의 `ValidateSet`이나 `Get-Verb`으로 대신하면 됩니다.

```powershell
if (-not (Get-Verb -Verb $Verb)) { throw "승인되지 않은 동사: $Verb" }
```

동사와 명사를 합친 이름이 곧 `New-ModuleForge`처럼 되고, 매니페스트의 `-CmdletsToExport @("$Verb-$Noun")`와도 일치합니다.

This example creates a new module manifest. It uses the **PowerShellVersion** and
    **AliasesToExport** parameters to add values to the corresponding manifest keys.

```powershell
 $moduleSettings = @{
        PowerShellVersion = 1.0
        Path   = 'C:\ps-test\ManifestTest.psd1'
        AliasesToExport   = @(
          'JKBC'
          'DRC'
          'TAC'
        )
    }
 New-ModuleManifest @moduleSettings
```
    This example uses a string format to specify the name of the **BitsTransfer** module and the hash
    table format to specify the name, a **GUID**, and a version of the **PSScheduledJob** module.

```powershell
    $moduleSettings = @{
      RequiredModules = ("BitsTransfer", @{
        ModuleName="PSScheduledJob"
        ModuleVersion="1.0.0.0";
        GUID="50cdb55f-5ab7-489f-9e94-4ec21ff51e59"
      })
      Path = 'C:\ps-test\ManifestTest.psd1'
    }
    New-ModuleManifest @moduleSettings
```
    
    This example shows how to use the string and hash table formats of the **ModuleList**,
    **RequiredModules**, and **NestedModules** parameter. You can combine strings and hash tables in the
    same parameter value.

     --------- Example 4 - Create a manifest that supports updateable help ---------

    This example uses the **HelpInfoUri** parameter to create a **HelpInfoUri** key in the module
    manifest. The value of the parameter and the key must begin with **http** or **https**. This value
    tells the Updatable Help system where to find the HelpInfo XML updatable help information file for
    the module.
    
    ```powershell
    $moduleSettings = @{
      HelpInfoUri = 'http://https://go.microsoft.com/fwlink/?LinkID=603'
      Path = 'C:\ps-test\ManifestTest.psd1'
    }
    New-ModuleManifest @moduleSettings
    ```
    
    For information about Updatable Help, see [about_Updatable_Help](About/about_Updatable_Help.md).
    For information about the HelpInfo XML file, see
    [Supporting Updatable Help](/powershell/scripting/developer/module/supporting-updatable-help).
